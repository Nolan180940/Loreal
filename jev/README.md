# jev-guard

基于 **jev-1.13 (TypeSafe AI System One)** 的小红书内容核验工具。

零训练、零标注依赖、可解释 —— 每条判定都能追到具体句子。

```bash
pip install -e .
python -m jev_guard doctor                      # 环境自检
python -m jev_guard label --kind note           # 打标
python -m jev_guard score                        # 风险评分
python -m jev_guard report --top 15              # 风险报告
python -m jev_guard inspect 6a957d1f             # 单条判定链路
```

---

## 为什么要这个项目

小红书内容核验（Track 2「信任守护」）需要一个判断器，回答两个问题：

1. 这篇内容**有没有夸大 / 误导性表述**？
2. 它**是不是商业推广**？

常见做法是训一个分类器。但当前条件下行不通：

- 采集到的 42 篇笔记**没有任何可信标注**（标注表与采集数据 ID 完全对不上）
- 42 个样本配 42 个特征，n/p = 1.0，且互动数共线性 0.76~0.96
- 实测帖子级逻辑回归剔除标签泄漏后 AUC=0.610，**置换检验 p=0.163 不显著**

而 jev-1.13 是 **System One 模型**：不生成文本，直接对 state 做带类型的判断，
返回概率。**这正好就是「判断器」**，且不需要训练。

实测 42 篇笔记的判断与人工直觉一致：

```
「此物对烂脸的杀伤力为100000%！！」
  → has_risk 0.95  exaggeration 3.0(extreme)  is_ad 0.88
```

## 架构

```
data/<note_id>/          ← xhs-cli 的采集产物（本项目不抓数据）
      │
      ▼
 extractors/reader.py    统一成 Subject，双 schema 兼容
      │
      ▼
 providers/jev.py        调用 jev-1.13，带限流/重试/成本统计
      │
      ▼  labels_<kind>.jsonl
 core/scoring.py         加权求和 + 阈值 + 证据抽取
      │
      ▼  scores.jsonl
 report / inspect        报告与单条链路
```

### 模块职责

| 模块 | 职责 | 关键设计 |
|---|---|---|
| `core/config.py` | 配置解析 | 优先级：默认 < 文件 < 环境变量 < CLI |
| `core/models.py` | 数据模型 | 全部 frozen + slots，保证不可变 |
| `core/questions.py` | 提问模板 | 独立成文件，便于diff 和 A/B |
| `core/scoring.py` | 规则引擎 | 纯函数，无 IO，单测覆盖 |
| `providers/jev.py` | HTTP 客户端 | UA 伪装（必须）、限流、退避重试 |
| `extractors/reader.py` | 数据读取 | **唯一知道双 schema 的地方** |
| `pipeline/` | 批处理 | 断点续跑是一等公民 |

## 核心设计决策

### 1. 不做分类器

| | jev-1.13 | 逻辑回归 |
|---|---|---|
| 需要标注 | 否 | 是 |
| 需要训练 | 否 | 是 |
| 样本要求 | 1 条 | n/p > 10 |
| 可解释性 | 定位到句子 | 只给系数 |

需要校准时用 `jev-guard calibrate` 拟合阈值，**代码不用改**。

### 2. 广告身份一票否决

加权平均会把「纯广告」稀释掉。实测 3 篇官方活动贴：

```
is_ad=0.96  exaggeration=0.47  has_risk=0.61  is_cta=0.48
→ 加权后仅 0.642，误判为中风险
```

**jev 判对了 `is_ad=0.96`，是加权平均把它拉下去的。**

加权平均假设各维度独立，但**广告身份是结构性的** —— 一篇官方活动贴
没有任何夸大宣称，可它 100% 是广告。

修复：`is_ad ≥ 0.85` 时直接判高风险，不参与加权。
阈值依据：3 篇官方活动贴 `is_ad=0.87~0.96`，真实 UGC 软广最高 0.79。

**注意只有 `is_ad` 参与短路。** 最初让所有维度都能短路，结果
`is_cta=0.88` 也被判高风险，反而误判了一篇成分党硬核测评 ——
强引导不等于高风险，真诚推荐也会有强引导。

效果：高风险召回率 **40% → 100%**。

### 3. 真实性只能减轻，不能洗白

```
total = max(0, dimension_value - 0.15)   # 检测到第一人称体验时
```

上限 0.15。理由：一篇真诚的测评说「能治痘」仍然是有害的。
且短路发生在折扣**之前** —— 真实性不能洗白广告身份。

### 4. 提问措辞必须实测校准

首轮检查发现 `has_risk` 对**真实测评系统性高估**。根因是把
「描述产品副作用」误判成「疗效宣称」：

```
"换了之后脸总是干痒刺痛"    → 旧 0.50（误判，这是消费者披露）
"这个面霜能治痘消炎"        → 旧 0.60（正确，这是违规宣称）
```

两者语义相反。改写措辞显式区分二者，22 次调用 A/B 实测：

| | OLD | NEW |
|---|---|---|
| 真阳性（绝对化宣称） | 0.885 | **0.855** 保住 |
| 真阴性（真实测评） | 0.437 | **0.182** 修复，零新误判 |

**改一句话，最终一致率 66.7% → 83.3%。**

### 5. 权重体现赛道优先级

```python
has_risk     = 0.35   # 医疗/绝对化/误导性承诺
exaggeration = 0.30   # 夸大程度
is_ad        = 0.25   # 商业推广身份
is_cta       = 0.10   # 购买引导（弱信号，营销号也常有）
```

夸大 > 软广：一篇真诚的广告仍是广告，一篇真诚的测评说「能治痘」是害人的。

### 6. 限流是常态

`jev-1.13-free` 是限时免费额度，实测 254 次请求后返回 429。

策略是**遇到限流优雅停下并保留进度**，而不是重试到死。
重跑同一命令自动跳过已完成的，成本为零。

### 7. 双 schema 兼容

`data/` 里混存两套 key：

- 早期 Spider_XHS：中文（`作品标题` / `点赞数量`），标签是空格分隔字符串
- 后期 xhs-cli：英文（`title` / `liked`），标签是数组

读取层同时认两套。上游只拿`Subject`，不感知差异。

## 实测准确度

以助手逐篇阅读正文做出的独立判断为基准（n=24，可比集）：

| 指标 | 加权平均 | +一票否决 | +措辞校准 |
|---|---|---|---|
| 完全一致率（3 档） | 58.3% | 66.7% | **83.3%** |
| 二值一致率 | 87.5% | 95.8% | **95.8%** |
| Cohen's kappa | 0.360 | 0.488 | **0.701** |
| 高风险精确率 | 100% | 83.3% | **100%** |
| 高风险召回率 | 40.0% | 100% | **80.0%** |
| 高风险 F1 | 0.571 | 0.909 | **0.889** |

最终混淆矩阵：

```
        high  medium low
high      4        1    0     ← 漏 1 篇「100000%」
medium    0        3    2
low       0        1   13     ← 误判已从 6 降到 1
```

⚠️ **这不是 ground truth**，是助手的独立判断。正式汇报前应由用户抽查确认。

## 关键发现：互动量不能判断真实性

jev 语义分与互动数的 Spearman 相关：

| 语义分 | 点赞 | 收藏 | **评论** |
|---|---|---|---|
| `is_ad` 广告 | +0.367 | **+0.382** | **-0.032** |
| `exaggeration` 夸大 | +0.306 | +0.411 | **+0.058** |

**软广能转化收藏，但不引发讨论；越夸张，点赞收藏涨，评论不涨。**

→ 如果 Agent 只看点赞/收藏判断真假，会被广告帖完全骗过去。

⚠️ n=42 时 Spearman 标准误约 0.15，仅供方向性参考。

## 踩过的坑

### Cloudflare 403 code 1010

第一次调用返回 `HTTP 403: error code: 1010`，**看起来像 key 无效**。

实测：同一个 key、同一端点，仅把 UA 从 `Python-urllib/3.x` 换成浏览器
字符串，**全部端点 403 → 200**。1010 = Cloudflare "browser signature banned"。

`BROWSER_UA` 不是可选项。

### PowerShell 输出乱码

Windows 控制台是 GBK。做法：**让脚本自己 `write_text(encoding="utf-8")` 写文件**，
再用编辑器读取，不要经过管道。CLI 内已 `reconfigure(encoding="utf-8")` 兜底。

### 小红书计数的两个坑

- `-1` 表示「无/未公开」，不是缺失 → 按 0 处理
- 搜索快照里是 `"1.2万"` → `int()` 会炸，需自定义归一化
