# forensic —— 美妆内容图像鉴伪取证模块（独立实现）

> 赛道2「信任守护师」· 图像侧产出。与 `D:\xhs-post-detector`（文本侧）**零依赖**，
> 全部代码从零实现，CPU 可跑，零大模型权重，零外部数据下载。

## 1. 它解决什么

判断一张小红书（美妆）配图是否被**篡改、拼接或伪造**，并给出**可复查的证据**：
可疑区域热区 + 逐维贡献 + 中文依据句。输出为「证据卡 JSON」，供下游 Agent 消费。

## 2. 架构（三层，别混淆）

```
证据层（无学习，CPU 毫秒~秒级）              融合层（可学习）           决策层（布尔门控）
┌────────────────────────────────┐   ┌──────────────────────┐   ┌──────────────────┐
│ x1 复制-移动（自相关+像素验证） │   │ p_LR = σ(w·x + b)    │   │ auto_flag: AND   │
│ x2 重压缩不一致 ELA（局部）     │──▶│ 6 维逻辑回归         │──▶│ review:    OR    │
│ x3 局部噪声异常                 │   │                      │   │ 降级: 仅 x1..x6  │
│ x4 直线接缝异常                 │   │ 可选第 7 维：        │   └──────────────────┘
│ x5 频谱斜率异常（不可定位）     │   │ x7 = logit(p_Jev)    │
│ x6 元数据/C2PA                  │   │ → logit 堆叠         │
└────────────────────────────────┘   └──────────────────────┘
         每维附热区                        权重由数据学出        逻辑门只在此层出现
```

**关键设计原则**（每条都来自实测踩坑，见第 6 节）：
1. 证据层不做学习，只做物理/统计测量；融合层才学习权重。
2. 每个特征的「异常」必须相对于**图像自身的局部基线**，而不是全局基线——
   否则整图重压缩/滤镜（硬负例）会全部误报。
3. 概率保持连续，布尔只在最后一步出现；冲突表现为中间档「不确定」。
4. 语义侧（Jev）是**可选**的第 7 维，任何失败都自动降级，绝不阻塞主链路。

## 4. 使用

```powershell
$PY = "d:\LOreal-ai\.venv\Scripts\python.exe"

# 0) 生成数据（可复现，种子固定）
$PY forensic\datagen.py data

# 1) 标定 + 提取特征 + 训练 + 阈值   （约 1.6 秒/图，310 图约 8 分钟）
$PY -m forensic.train

# 2) 评估报告
$PY -m forensic.eval

# 3) 单图证据卡（离线，断网可用）
$PY -m forensic.cli analyze data\images\s001.png --out card.json

# 4) 语义侧冒烟（需 OPENCODE_API_KEY，未设置则记为未接通）
$PY -m forensic.cli jev-smoke
```

## 5. 六个特征各自负责什么

**分类性能（val，程序化合成集）**：AUC 0.8431、AP 0.8847；三段判定在
$\tau_{low}=0.764$ 下 val 误报率 4.44%。

**定位性能（热区 vs 掩码，阈值 0.35）**：

| 缺陷 | 最佳单特征 | 单特征命中 | 融合命中 | 融合 IoU |
|---|---|---:|---:|---:|
| 复制-移动 | x1 | 0.533 | 0.533 | 0.372 |
| 拼接 | x2 | 0.986 | 0.983 | 0.324 |
| 涂改数字 | x2 | 1.000 | 1.000 | 0.293 |

定位是**逐特征互补**的：x1 负责复制-移动，x2 负责拼接与局部重压缩。融合热区在
`evidence.fuse_heats` 里生成（逐像素取最大 + 面积过滤）。

| 特征 | 机制 | 定位 | 主要覆盖 | 已知盲区 |
|---|---|---|---|---|
| x1 | 高通 + FFT 自相关找位移 + 像素差连通域验证 | ✅ | 复制-移动 | 小面积低方差复制；重压缩后衰减 |
| x2 | 重压缩残差在**同相位**邻块间的区域性离群面积（8px 块） | ✅ | 拼接、涂改、局部重压缩不一致 | 良性重压缩与之同类，属本质歧义（见 6.9） |
| x3 | 中值残差噪声水平与邻域基线的离群度 | ✅ | 纯色填充、抹除、AI 平滑 | 噪声被整图重构的情况 |
| x4 | 高通能量与亮度剖面在小行/列上的孤立尖峰 | ✅ | 直线接缝、不同锐度拼接 | **弱信号**，见 6.8 |
| x5 | 径向功率谱斜率偏离参考值 | ❌ | 整图级处理、AI 生成（辅助信号） | 无定位、不能单独定案 |
| x6 | EXIF / C2PA 内容凭证 | ❌ | 有可信签名时是强真证据 | 平台转存必清空 → 缺失只记中立 0.5 |

## 6. 开发中踩过的坑（重要，避免回退）

1. **分块匹配对随机位移无效**：块网格与复制位移不对齐时，被复制内容在网格上的
   采样相位不同，块描述子永远不相等 → 真阳性恒为 0。改用全域自相关。
2. **描述子池化过度**：4×4 均值池化（16 维）丢掉高频结构，不同纹理块互相匹配 →
   干净图满匹配。必须保留块内细节。
3. **全局基线比较 = 大量误报**：整图重压缩/滤镜会整体抬高 ELA 与噪声统计量，
   用全局中位数当基线会把硬负例全判成异常。必须与**邻域**基线比较。
4. **极值统计量必须标定**：`max|z|` 在几千个块上即使全是干净图也能到几十，
   固定阈值要么全异常要么全正常。必须在**干净训练集**上标定映射区间。
5. **自相关必须先前置高通**：否则大尺度结构（垂直渐变在水平位移下几乎不变）
   完全淹没复制峰。
6. **峰检测要做大半径 NMS**：宽平台用小半径检测会被切成上千个点，真实峰排名虚高
   （实测 21~1587 名）；40px 半径 NMS 后每个平台只留一个代表点。
7. **验证步骤要先做廉价预筛**：全图开运算+连通域每候选约 10ms，不做预筛时每图 >3s；
   瓦片预筛后降到 ~1s/图。
8. **拼接信号的负面结论（重要，别重复踩）**：
   - 若拼接两半来自同源同曝光图像，像素级**不存在**可检测证据：
     实测 DC 台阶 8.75（拼接）vs 8.75（干净图），高频剖面也几乎相同。
     这类样本是「无真实对应物的伪难度」，应修正生成器而不是硬调算法。
   - 即使注入真实的前后对比曝光差（gain 0.85 / bias ±12），台阶会被 1px 羽化
     与高斯平滑摊到约 25 像素宽，逐像素梯度（~2.5 灰阶）与图内软边物体同量级，
     **仍不足以稳定区分**。两个失败的归一化写法已记录在 `extract_x4` docstring 中。
   - 结论：**拼接的像素级亮度台阶不是可靠线索**；实际由 x2（ELA 相位对齐）
     检出（拼接归一化值 1.000 vs 干净图 0.000）。
9. **分析网格必须与 JPEG 网格同尺度、同相位（最重要的一个修复）**：
   - 用 16px 网格去量 JPEG 的 8px 块效应会产生**拍频混叠**：16px 块跨两个不同
     相位的 JPEG 块，块效应表现为周期性抖动，被误判为「区域异常」。后果：
     JPEG 硬负例的 ELA 异常度被推到 1.0，LR 只能学出**负权重**（-0.395）——
     特征语义反了的典型征兆。
   - 改为 8px 块 + 与间隔 2 块（=16px=同相位）的邻居比较后，周期性块效应抵消：
     干净图 0.000 / 涂改数字 1.000 / 拼接 1.000，权重翻正为 +1.078，
     AUC 0.837→0.843，干净图误报率 0.13→0.00。
   - 配套细节：z 必须稳健截断（退化时 MAD→0，实测单图 z 达 2.2e6）。
10. **良性重压缩与局部篡改是本质歧义（当前性能天花板）**：JPEG Q70/Q90 硬负例在 x2
    上同样得 1.000，与拼接/涂改无法区分 —— 因为双重压缩本身就留下「区域压缩历史
    不一致」痕迹，与篡改同类。这是领域公认困难，不是实现缺陷。彻底解决需显式估计
    压缩历史后再归一化（后续工作）。
11. **键名前缀不一致会让可视化静默失效**：`features.extract_all` 的热区键是短名
    （`x1..x6`），而 LR 贡献的键是完整名（`x1_copy_move` 等）。`_overlay` 里
    `weights.get("x1")` 恒为 0 → **所有热区被跳过、overlay 完全没有高亮**，
    而程序不报任何错。修法是做前缀归一化。
    - 教训：**可视化必须做像素级自检**（统计"红色高亮像素数"），不能只看文件是否生成；
      本次是靠 View Image 肉眼发现图片"看起来像原图"才暴露的。
12. **热区必须稀疏**：若直接对 z 图做 max-min 归一化，会因图中普遍存在的温和偏差
    把整幅图标红（实测 x3/x4 覆盖 100% 与 26% 像素，等于没有定位）。修法是先阈值化
    （x3 用 `|z|>k` 的块；x4 取最离群的 top-K 行/列）再归一化，实测降到 4.9% 与 2.5%。

## 7. 诚实性纪律

- 报告数字全部来自**程序化合成集**，不得宣称真实平台准确率。
- `no_anomaly_supported` = 「未发现所支持的异常」，**不是**「证明为真」。
- `ai_like` 是频域扰动**占位**样本，不是真实 AI 生成图，单独统计。
- 真实图片与人工标注到位后，接入同一 schema 重跑即可，无需改代码结构。
