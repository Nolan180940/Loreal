## 2. 关键设计决策（含否决的方案）

| 决策 | 理由 |
|---|---|
| 证据层不学习、融合层才学权重 | 取证算法是物理/统计测量，没有可训练参数；权重由 LR 在数据上学出 |
| 每个特征与**图像自身局部基线**比较，不用全局基线 | 整图重压缩/滤镜是硬负例；全局基线会把它们全判异常（实测旧版 ELA/噪声在 JPEG Q90 上 = 1.0） |
| 极值统计量必须**在干净训练集上标定映射区间** | `max|z|` 天生重尾，固定阈值必然全异常或全正常（实测全类别饱和到 1.0） |
| 概率保持连续；布尔只在门控层出现 | 布尔会丢掉置信度、无法表达冲突、无法学权重 |
| 融合用 **logit 加权**（stacking）而非概率相加 | 概率和有天花板；logit 空间可加权、可解释为赔率相乘 |
| Jev 只作**可选第 7 维**，失败自动降级 | 官方规格不支持图像；依赖外部 API，演示断网风险；降级后链路照跑 |
| 拼接样本必须注入照明/曝光差异 | 同源同曝光的拼接在像素上**不存在**可检测证据（见第 3 节），属伪难度 |
| 自动打标用 AND、人工复核用 OR | 误伤博主代价 > 漏放；两种语义用布尔表达最清晰且行为可预期 |

## 3. 已验证与已证伪的技术结论（重要，避免团队重复试错）

**成功**
1. **分块匹配对随机像素位移无效** → 改用 FFT 自相关全域搜索。效果：复制移动召回 12/15，干净图零误报，0.99 秒/图。
2. **自相关必须前置高通**，否则大尺度结构（垂直渐变在水平位移下不变）淹没复制峰。
3. **峰检测必须大半径 NMS（40px）**，否则宽平台被切成上千点、真实峰排名虚高（实测 21~1587 名）。
4. **验证前必须廉价预筛**（16px 瓦片、60% 命中率），否则每图 >3 秒。
5. 涂改数字：**100% 检出**（填充区在 x1/x2 上有明确响应）。
6. **ELA 必须与 JPEG 网格同尺度、同相位比较**（本次最重要的修复）：
   - 旧版用 16px 网格量 JPEG 的 8px 块效应 → **拍频混叠**，块效应在 16px 尺度
     表现为周期性抖动，被局部基线误判为"区域异常"。后果：JPEG 重压缩硬负例的
     异常度被推到 1.0，LR 只能学出**负权重 -0.395**（特征语义反了）。
   - 改为 8px 块 + 与间隔 2 块（=16px = 同相位）的邻居比较后：干净图 0.000、
     涂改数字 1.000、**拼接 1.000（旧版完全检不出）**，权重翻正为 **+1.078**，
     AUC 0.837 → 0.843，干净图误报率 0.13 → 0.00。
   - 附带的必要细节：z 必须稳健截断（退化时 MAD→0，实测单图 z 达 2.2e6）。

**证伪 / 已知盲区（如实记录）**

6. **拼接的「亮度台阶」路线行不通（已改用 ELA 相位对齐路线解决）**：
   - 同源同曝光拼接：DC 台阶 8.75 vs 干净图 8.75 —— 绝对无信号；
   - 注入真实曝光差（gain 0.85、bias ±12）后：台阶被 1px 羽化 + 高斯平滑摊到约 25px
     宽，逐像素梯度 ≈2.5 灰阶，与图内软边物体同量级 —— 不足以稳定区分；
   - 三种归一化写法均已证伪：MAD 归一化（退化时虚高到 1e6）、
     绝对灰阶下界（下界 2.6 压死信号，所有类别收敛到 ~1.0）、
     中值滤波基线（会把单调台阶抵成 dev≈0）。
   - **结论：亮度台阶不是可靠线索；拼接改由 x2（ELA 相位对齐）检出。**

7. **良性重压缩与局部篡改是本质歧义（当前主要性能天花板）**：
   - 实测 JPEG Q70/Q90 硬负例在 x2 上同样得到 1.000，与拼接/涂改数字无法区分 ——
     因为双重压缩本身就会留下「区域压缩历史不一致」的痕迹，与篡改同类。
   - 这不是实现缺陷，而是图像取证领域的公认困难。当前只能靠阈值与其它维度联合压制。
   - **彻底解决需显式估计压缩历史后再归一化（列为后续工作）。**
7. **x5（频谱斜率）只作辅助**：无定位能力，且相机-社交平台链路会改变谱特征。
8. **x6（元数据）缺失只记中立 0.5**：平台转存必清空 EXIF/C2PA，缺失不能当证据。

## 4. 当前性能（程序化合成集，非真实平台指标）

**分类（val = 93 条）**：AUC 0.8431（bootstrap 95% 区间 0.7547–0.9184），AP 0.8847。
双阈值 $\tau_{low}=0.764$、$\tau_{high}=0.814$，val 误报率 4.44%（目标 ≤ 5%）。

| 类型 | n | 平均 p | 判可疑比例 |
|---|---:|---:|---:|
| 涂改数字 | 15 | 0.932 | **1.00** |
| 复制-移动 | 15 | 0.645 | 0.53 |
| 频域占位 | 3 | 0.766 | 0.33 |
| 拼接 | 15 | 0.600 | 0.33 |
| 硬负例（各类变换） | 24 | 0.40 | 0.04 |
| 原始干净 | 15 | 0.248 | **0.00** |

**定位（热区 vs 掩码，阈值 0.35）**：

| 操作 | x1 IoU | x1 命中 | x2 IoU | x2 命中 | 融合 IoU | 融合 命中 |
|---|---:|---:|---:|---:|---:|---:|
| copy_move | 0.525 | 0.533 | 0.045 | 0.082 | 0.372 | 0.533 |
| splice | 0.000 | 0.000 | 0.294 | 0.986 | 0.324 | **0.983** |
| digit_edit | 0.125 | 0.128 | 0.358 | **1.000** | 0.293 | **1.000** |

- 定位能力**逐特征互补**：x1 负责复制-移动；x2 负责拼接与局部重压缩。
- 融合热区用「逐像素取最大」（只取正向贡献特征）并滤掉面积 < 0.2% 画面的孤立
  连通域。取最大是因为加权求和会被主导特征稀释（复制样本上 x1 贡献 +10.7、
  x2 仅 +0.39，但 x1 热区会因偶然匹配偏离真实位置）；面积过滤则去掉 x3/x4 的
  散点噪声（实测使融合 IoU 全线提升：0.295→0.372、0.245→0.324、0.221→0.293）。
- 代价：copy_move 的 IoU 从 x1 单用时的 0.525 降到 0.372（热区面积变大）。这是
  **召回优先**的取舍：交付要求是标出可疑处供人工复核，漏标比多标代价更高。
- 已目视验证：复制-移动样本的热区精确命中真值 `src=[541,162]` 与 `dst=[832,336]`。

## 7. 已修复的真实 bug（含症状与排查路径，便于团队复用）

| 症状 | 根因 | 修法 |
|---|---|---|
| overlay 图看起来像原图，完全没有高亮，但程序不报错 | `heats` 键为 `x1..x6`，`contribs` 键为 `x1_copy_move`，`weights.get("x1")` 恒为 0 → 全部热区被静默跳过 | 键名前缀归一化；**并对可视化做像素级自检**（统计红色高亮像素数） |
| x3/x4 热区覆盖 100% / 26% 画面，定位无意义 | 直接对 z 图做 max-min 归一化，图中普遍存在的温和偏差把整图拉亮 | 先阈值化再归一化（x3 用 `\|z\|>k` 块；x4 取最离群 top-K 行/列），降到 4.9% / 2.5% |
| val 误报率 8.9% 而非目标 5% | 阈值下标算术 off-by-one（判据是 `p >= tau`，阈值取到负样本分数本身时该样本仍计入误报） | 改为可证明正确的搜索：取最小可行阈值 |
| x2 学到负权重 -0.395，特征语义反了 | 16px 网格量 8px JPEG 块效应 → 拍频混叠，硬负例被推成 1.0 | 改 8px 块 + 同相位邻块比较（间隔 2 块），权重翻正 +1.078 |
| x1 真阳性恒为 0 | 分块网格与随机像素位移不对齐，采样相位不同使块描述子永不相等 | 改 FFT 自相关全域搜索 + 高通前置 + 大半径 NMS + 瓦片预筛 |
