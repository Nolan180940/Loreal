## 1. S1 提问→回答时间差

**提议**：提问与回答间隔极短（1 分钟内）= 水军派单。

**数据现状**：
- 评论有 `time`（毫秒）✅
- 楼中楼有 `_parent_id`，但**父评论没有 id**（xhs-cli 丢掉了 SSR 里的 `id` 字段），
  `_parent_id` 指向的 id 在数据里**找不到对应对象** → 无法精确配对「哪条回复回答了哪条提问」
- 「哪条是提问」本身是语义判断，统计层做不了

**实测**：用「同楼中楼组内相邻时间差 ≤ 60s」做代理，AUC = **0.500**（无区分力）。
全库 200 个楼间差里只有 9 个 ≤1min，且高低风险篇分布无差异。

**为什么没区分度**：真实互动（作者答疑）本来就快；水军派单反而常隔几小时。
「快」本身不是水军特征，**「快 + 统一口径」才是**（那是 S6）。

**结论**：单独做没价值。它的正确形态是 S6 的组成部分（负面→快速辩解）。
前置条件：xhs-cli 补采 `id` 字段（§8）。

## 2. S2 极端肯定词 + 狂热 emoji

**提议**：「绝了/神仙/锁死/无限回购/亲测有效」+ 😭🥺✨🔥❤️ 连用 2 个以上。

**实测**（词表 16 词 + emoji 正则，543 条评论）：

| 特征 | 命中 | AUC |
|---|---|---:|
| 极端词占比 | 全库仅 3 条评论命中（冲×2、种草×1） | 0.552 |
| emoji 连用 ≥2 | **0 条** | 0.484 |

**为什么这么稀**：小红书评论的表情是 `[笑哭R]` 这种**平台表情码**，
不是 Unicode emoji。狂热 emoji（😭✨🔥）在**正文**里常见，在评论里几乎不用。
emoji 连用检测在评论层是空转。

**结论**：
- emoji 连用：**不做**（评论层无数据）
- 极端词：**不单独做**，把词表**合并进现有 `low_effort_ratio` 的反义词表**
  （low_effort 测「没信息量」，极端词测「只有情绪没信息」，是同一枚硬币的两面）。
  合并后看 AUC 是否从 0.742 再往上走 —— 这是零成本的实验。

## 3. S3 品牌全称 vs 简称

**提议**：水军写全称+型号（SEO/考核），真人写简称（「那个水乳」）。

**实测**：
- 用笔记自己的 tags 当品牌词表：评论含品牌词的占比 AUC = **0.607**
- 「某品牌/那个牌」简称形态：全库 **0 条** —— 真人也不这么写，
  他们直接说「珂润」「那个面霜」，简称检测没有可靠的词表锚点

**为什么方向是对的但只有 0.607**：品牌全称出现确实在 high 篇更密
（雅诗兰黛官方帖 33 次），但它混着两个来源：真人提问也会打全称（「雅诗兰黛小棕瓶多少钱」）。
纯计数分不开「水军夸」和「真人问」。

**结论**：**可做，中等价值**。改进方向不是加词表，而是**组合条件**：
「品牌全称 + 正向词 + 楼中楼/一级位置」三条件同时命中才算。
预期 AUC 能上 0.65~0.70，但要先修好 S5 的点赞数据才能验证「正向」。

## 4. S4 短时密集涌入 + 断崖 ⭐ 本轮最强

**提议**：发布后 10min~1h 内大量同方向评论，随后断崖。

**实测**（发布时间 `note.time_ms` vs 评论 `time`，38 篇可算）：

| 特征 | AUC | 说明 |
|---|---:|---|
| 发布后 1h 内评论占比 | **0.690** | |
| 发布后 24h 内占比 | 0.706 | |
| 断崖度（1h 内 / 24h 内） | 0.656 | |

**典型案例**（`6abc9b7b`，gold=high）：

```
发布 09-30 14:34
+34min  小一    白天涂完跟防晒搓泥…
+43min  真的在学 这真是要冲一把了
+57min  嗇。    博主说白天抗氧化化…
+4533min（3天后）…
```

前 1 小时 3 条，然后 3 天没有 —— 正是组员描述的形态。

**注意**：现有 `comment_time_span`（AUC 0.737）测的是「5 条一级评论内部跨度」，
S4 测的是「相对发布时间的爆发」。两者相关但不同 —— S4 有绝对时间锚点，
且能被楼中楼数据增强（一级只有 5 条，加上楼中楼时间样本翻 4 倍）。

**结论**：**做**。这是 7 个提议里唯一 AUC 接近现有最强信号的。
实现为 `publish_burst`：`发布后 1h 内评论占比`，样本下限 5 条。
风险：一级评论只有 5 条（平台限制），占比的粒度是 0.2 ——
必须把楼中楼时间也算进来才够密。

## 6. S6 负面评论下的统一口径辩解

**提议**：质疑评论（不好用/智商税）下方迅速出现多条统一口径辩解。

**实测**：
- 负面评论（12 词词表）：15 条 / 12 篇 —— 样本极稀
- 辩解词（没用对/个体差异/因人而异…）：全库 **1 条**
- 结构障碍：一级评论没有 id，**无法可靠定位「某条负面评论的回复」**
  （现在用「位置上紧跟的楼中楼」近似，一级评论混排时必错）

**真实案例倒是有的**（`6a957d1f`，gold=high）：

```
09-02 01:34 [挖宝小孟] 可以
09-02 01:34 [挖宝小孟] 上面就写了 专为敏感肌
09-02 01:35 [挖宝小孟] 真的
```

同一账号 1 分钟内 3 条楼中楼 —— 这就是「统一口径快速刷」的活样本。
但它被 S7 的跨帖/同帖高频检测抓更准（这个账号跨 2 篇发 10 条）。

**结论**：**改形态**。不做「负面→辩解」这个脆弱链路，做它的两个可计算组件：
1. **同账号同帖高频发言**（≥3 条）—— 已算 AUC 0.378，方向反了，见 §7
2. **同账号跨帖重复出现** —— 见 §7

「统一口径」的文本相似度检测等评论 id 修复 + 样本多了再说。

## 7. S7 账号真实度 / 跨帖重合

组员这一条其实是 **5 个子信号**，逐个查：

| 子信号 | 数据可得？ | 实测 | 结论 |
|---|---|---|---|
| 小红书号纯数字/乱码 | ❌ SSR 的 user 对象只有 `nickname/image/aiAgent/userId` 4 键，**没有小红书号** | — | 不可得 |
| 主页无原创笔记 | ❌ 用户主页是登录墙（字段可用性表已实测） | — | 不可得 |
| 关注/粉丝比 | ❌ 同上，主页数据 | — | 不可得 |
| IP 属地聚集 | ✅ 已有 | `ip_top1_ratio` 0.511 / `ip_entropy` 0.460 | **已做，本样本无区分度** |
| **跨帖评论重合** | ✅ **现有 43 篇数据就能算** | 见下 | **可做** |

**跨帖重合实测**：374 个唯一 user_id 里，**3 个**出现在 ≥2 篇：

```
[v薇薇]    2 篇：不会 / 不如珂润好用 / 珂润水？
[挖宝小孟]  2 篇 10 条：找我 / 是的 / 可以的呀 / 可以 / 真的…
[幸运倩倩]  2 篇：免洗面膜确实很方便！ / 这款对敏感肌肤效果如何？
```

`挖宝小孟` 是教科书级样本：跨 2 篇发 10 条，内容全是 2~4 字的空洞应答
（「找我」「是的」「可以」「真的」），IP 在浙江/上海间跳。
**但**：同帖高频发言占比的 AUC = **0.378（反向）** ——
high 篇里 4 篇的 heavy_talker_ratio 是 0.00，low 篇反而一堆长评答疑党。

**为什么反向**：真实分享帖的评论区就是「作者+热心路人来回答疑」，
一人发 4 条很正常（`693abce3` 的 [飘来飘去hba] 发 4 条专业长评）。
**「高频」不是特征，「高频 + 内容空洞 + 跨帖重复」才是。**

**结论**：**做「跨帖重合」这一个**，形态定为：
`跨帖空洞评论占比` = 出现在 ≥2 篇且内容 ≤6 字的评论 / 总评论。
当前 43 篇里这个值几乎全 0（只有 3 个用户），**单篇内区分度有限**，
但它的正确用法是**账号级黑名单**：跨帖用户直接进 `shill_accounts` 集合，
判定时该账号的评论按「已证实水军」计权。这需要把信号层从「单篇独立」
改成「允许读全局账号索引」—— 是个架构改动，见 PLAN。

## 8. 调查中的意外发现：采集层丢了 6 个关键字段 ⭐⭐

对 7 个提议查数据可得性时，发现 **xhs-cli 的 SSR 解析丢掉了原始数据里的
6 个字段**，其中两个直接卡死了 S1/S5/S6：

| SSR 原始字段 | xhs-cli 现状 | 影响 |
|---|---|---|
| `id`（评论 id） | **丢弃** | S1/S6 无法精确配对父子评论；`_parent_id` 成了悬空指针 |
| `likeViewCount` | **丢弃**（只取了 `likeCount`） | **`likeCount` 恒 0 是采集 bug**：`likeViewCount` 才是展示值，实测有 `310/56/24/29/32` 这种真值 |
| `subCommentCount` | 丢弃 | 无法判断楼中楼是否抓全 |
| `status` | 丢弃 | 实测 -2=审核中/仅自己可见（卖家帖 5/5 全是 -2），本身是个信号 |
| `commentType` | 丢弃 | 语义未查 |
| `user.aiAgent` | 丢弃 | **官方 AI 账号标记**（实测 False，但字段存在） |

**`likeViewCount` 的发现直接推翻了一个既有结论**：
`comment_like_rate` 信号「恒 missing」的原因不是「平台不填充」，
而是**采集时取错了字段**。修一行采集代码，这个 AUC 未知的信号就能激活。

**验证记录**（6ab6a30e 雅诗兰黛官方帖）：

```
一级评论 likeViewCount: ['310', '56', '24', '29', '32']   ← 真实展示值
一级评论 likeCount:     [0, 0, 0, 0, 0]                  ← 恒 0（内部计数器？）
楼中楼 likeViewCount:   ['53', '6', '0', '25', '0', ...]
```

## 9. PLAN

### P0：修采集（前置，半天）✅ 已完成

`xhs-cli/src/xhs_cli/core/ssr_json.py` 的 `parse_comments_json` 补 4 个字段：

"id": str(c.get("id") or ""),                    # 评论 id（S1/S6 的配对键）

## 10. 实施记录（2026-10-11）

### P0 修采集 ✅

`xhs-cli/src/xhs_cli/core/ssr_json.py` 补 4 字段，慢路径（正则保底）
同步补齐以保持字段集一致：

| 字段 | 快路径 | 慢路径 |
|---|---|---|
| `id` | ✅ 从 SSR 取 | ⚠️ 留空 —— `"id":"..."` 在 user/note 里到处出现，按最近距离配对必然错配。**宁可空也不给错值** |
| `like_view_count` | ✅ | ✅ |
| `sub_comment_count` | ✅ | ✅ |
| `status` | ✅ | ✅ |
| `_parent_id` / `target_id` | ✅ | ✅（从 `targetComment.id` 正则取） |

**顺带统一了字段集**：一级评论原来没有 `_parent_id` / `target_id`，
现在补空值 —— 下游不用写 `if "_parent_id" in c` 这种分支。
代价是不能再靠「键存在」判断层级，但那本来就该看 `_is_reply`。

实测（重抓 69d8c8a6）：
- 6 个新字段全部落盘（13/13 条评论）
- **`_parent_id` 8/8 命中同篇 `id` 集合**（之前是悬空指针）
- `comment_like_rate` 从恒 missing → **0.615**（真值）
- `likeViewCount` 语义判定依据：某帖 5373 赞 / 1980 评论，其热评该值
  只有 310/56/24 且多条为 0 —— 若是「浏览量」不可能这么低

### P1 两个新信号 ✅

| 信号 | AUC | 阈值 | 上限 | 备注 |
|---|---:|---|---:|---|
| `publish_burst` | **0.691** | `_LO=0.05` `_HI=0.35` | 0.7 | 窗口扫过 5/10/30/60/180/1440 分钟 |
| `brand_mention_ratio` | **0.594** | `_LO=0.10` `_HI=0.70` | 0.6 | 词表覆盖率 30/40 → 37/40 |

**两个都踩了同一个坑：阈值定在分布之外。**
`publish_burst` 先写 `_LO=0.15`，但 6 篇 high 里 4 篇的占比低于它 →
全被压成 0，AUC 从 0.683 掉到 0.478。
`brand_mention_ratio` 先写 `_HI=0.30`，但实测 p75=0.438 →
大半篇被压成同一个值，AUC 0.589 → 0.578。

→ 教训（已写进两个信号的 docstring）：**定阈值前先看分布**，
`_HI` 必须高于 p75，`_LO` 必须贴近最小值。

**10 分钟窗口的发现**：组员强调的是「10 分钟至 1 小时」，
但 10 分钟窗口 AUC 只有 0.495。这不是「组员说错了」，是
**我们的采样看不见** —— 匿名态每篇只给 5 条一级评论 + 楼中楼，
十几条里凑不出 10 分钟窗口。要验证得先有全量评论流。

**`brand_mention_ratio` 的两处反直觉结论**：
1. 品类词停用表（面霜/精华/护肤…）**降低** AUC（0.589 → 0.543）。
   说明品类词也带信号 —— 水军写「这个面霜真的很好用」，
   真人写「我用了三个月皮肤稳定了」（根本没提产品）。
   所以这个信号实际测的是「**评论有多产品导向**」。
2. 词池（`_lexicon.py`，自动生成）把覆盖率从 30/40 提到 37/40。
   必要性来自 tags 解析会失败（43 篇里 7 篇只剩假标签「笔记」）。

### P2 极端词并入 low_effort ❌ 决定不改

离线模拟（不动源码）结果：

| 版本 | AUC |
|---|---:|
| 现行（长度规则） | 0.742 |
| 并入极端词 | 0.742 |

**差异 0 条 / 540**。判据是「≥0.76 才保留」，未达成。

原因不是数据不够，是**结构性的**：能「只有极端词」的评论必然很短
（「绝了」2 字、「闭眼冲」3 字），早被 `max_len=8` 收进去了。
而极端词出现在**长评**里时（实测「……熟龄肌抗老闭眼冲。」）
它就不是低信息量 —— 强行去掉词会把详实长评误判成打卡。

→ 已写进 `low_effort_ratio` 的 docstring：**以后不要重试这个改法**，
除非 `max_len` 先被改小。

另外核实了极端词在评论层的出现率：**540 条里只有 4 条**（0.7%）。
组员列的词表在**正文**里常见，在**评论**里几乎不用。
